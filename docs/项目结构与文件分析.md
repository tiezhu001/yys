# 项目结构与文件分析

## OAS 服务端

- `server.py`：启动 FastAPI/Uvicorn 服务，默认读取 `config/deploy.yaml` 的 WebUI 地址和端口。
- `script.py`：脚本主循环和任务调度入口。
- `module/server/`：HTTP、WebSocket、配置、脚本进程和诊断接口。
- `module/device/`：设备连接、截图、点击和滑动。
- `module/atom/`：图像匹配、OCR、点击规则等基础动作。
- `module/config/`：配置模型、菜单和调度器。
- `tasks/`：具体游戏任务；`tasks/Component/` 放可复用任务组件。
- `tasks/Component/GeneralInvite/`：组队邀请、队员接受邀请和房间等待逻辑。
- `tasks/Orochi/`：御魂副本任务和配置。
- `config/`：运行配置，尤其是 `deploy.yaml` 和任务配置文件。
- `tests/`：静态单元测试和组件测试。

## OASX 客户端

- `lib/views/`：Flutter 页面布局，例如登录、总览、参数、服务端设置。
- `lib/controller/`：页面状态和用户操作控制器。
- `lib/api/api_client.dart`：HTTP API 客户端，负责连接 OAS 地址。
- `lib/service/`：脚本状态、WebSocket 日志和网络服务。
- `lib/model/`：接口数据模型。
- `lib/controller/nav_menu/`：左侧任务菜单数据。
- `lib/controller/server/server_controller.dart`：客户端内置的 OAS 启动逻辑，目前按整合包 `toolkit` 结构设计。
- `pubspec.yaml`：Flutter/Dart 依赖和版本约束。
- `.github/workflows/release-windows.yml`：Windows 发布构建流程。

## 改动边界

任务行为、OCR、点击坐标和调度器修改优先在 `oas` 完成；页面布局、按钮、客户端缓存和登录流程修改在 `oasx` 完成。增加配置字段时，需要同时确认 OAS 的字段描述和 OASX 当前支持的控件类型。
