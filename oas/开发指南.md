装包（venv 由 uv 管理，不要用 `pip` 直接装）：

```powershell
uv pip install <pkg> --python .\.venv\Scripts\python.exe
```

三条**不可违反**的环境约定：

1. **cwd 必须是仓库根**。`module/logger.py:59` 在 import 阶段就 `os.chdir(仓库根)`，`module/config/config_model.py` 用 `Path.cwd()/"config"` 读配置。从别的目录启动 = 读不到配置、日志写到奇怪的地方。
2. **`setuptools` 不要升级**（当前钉在 `80.10.2`）。84.x 移除了 `pkg_resources`，`adbutils` / `uiautomator2` 会直接 `ModuleNotFoundError`。
3. **`config/deploy.yaml` 里的 `AutoUpdate` 必须保持 `false`**，否则启动时 `git pull` 会覆盖你的改动（`KeepLocalChanges: true` 是配套项）。

环境细节（uv / Python 3.10.22 / PySide6-Essentials 6.4.3 / 为什么清华镜像会 403）都在 `AGENTS.md`。

## 2. 分层心智模型

```
┌──────────────────────────────────────────────────────────────┐

│  module/               框架层：与具体游戏无关的机制             │
│    atom/    RuleImage / RuleClick / RuleOcr / RuleSwipe …      │
```

## 3. 一次任务的完整生命周期

```
config/oas1.json                     ← 用户配置（pydantic 序列化）
      │
      ▼
ConfigModel（module/config/config_model.py）  ← 反序列化 + 默认值
      │  config.<task>.scheduler.enable / priority / next_run
      ▼
Script.loop()（script.py）                     ← 主调度循环
      │  TaskScheduler 按 FILTER/FIFO/PRIORITY 选出 pending 任务
      │  instance_guard（多开排队）→ anti_ban_guard（风控）
      ▼
Script.run(command)                            ← script.py:540
      │  load_module('script_task', './tasks/<Command>/script_task.py')
      ▼
ScriptTask(config, device).run()
      │  self.goto_page(...) / self.appear(...) / self.click(...)
      ▼
BaseTask（tasks/base_task.py） → Device（module/device/）
      │  screenshot() → cv2.matchTemplate / ppocr → click(x, y)
      ▼
1280×720 的游戏画面
      │
      ▼
set_next_run(...) + raise TaskEnd            ← 任务必须主动结束
```

异常出口（`script.py` 的 `run()`）：

| 异常 | 后果 |
|---|---|
| `TaskEnd` | 正常结束 |
| `GameNotRunningError` | 转 `Restart` 任务 |
| `GameStuckError` / `GameTooManyClickError` / `GameBugError` | 记一次失败 |
| `GamePageUnknownError` | 转 `Restart` + `device.sleep(10)` |
| `ScriptError` / `RequestHumanTakeover` / 其他 `Exception` | **`exit(1)` 杀掉整个进程** |

同一个任务连续失败 3 次 → `logger.critical` + 推送通知 + `exit(1)`。

## 4. 资源与规则系统：JSON → `assets.py`

这是本项目最特殊、也最容易踩坑的地方：**`assets.py` 不是手写的，是从同目录的 JSON 编译出来的**。

```
tasks/Orochi/o/image.json  ──[dev_tools/assets_extract.py]──▶  tasks/Orochi/assets.py
   (你改这里)                                                    (不要手改)
```

### 4.1 五类规则文件

一个 JSON 文件的顶层是 **list** 或 **dict**，生成器只看 `data[0]` 的字段来判断它是什么类型：

| 类型 | 顶层结构 | 判据（`dev_tools/assets_extract.py:293-359`） | 生成 |
|---|---|---|---|
| image | `list` | 含 `imageName` | `I_xxx = RuleImage(...)` |
| click | `list` | `len(item) == 4` | `C_xxx = RuleClick(...)` |
| long_click | `list` | 含 `duration` | `L_xxx = RuleLongClick(...)` |
| swipe | `list` | 含 `mode` 且 `len(item) == 5` | `S_xxx = RuleSwipe(...)` |
| ocr | `list` | 含 `keyword` | `O_xxx = RuleOcr(...)` |
| list | `dict` | dict 且含 `name` | `L_xxx = RuleList(...)` |

⚠️ **`RuleLongClick` 和 `RuleList` 共用 `L_` 前缀**（生成器 `:129` 与 `:242`），只能靠右边的类名区分。

### 4.2 字段 ↔ 生成结果

**image**（`o/image.json`）：

```json
[
  {
    "itemName": "orochi_check_10",
    "description": "御魂十层检查标志",
    "roiFront": [440, 40, 400, 100],
    "roiBack": [440, 40, 400, 100],
    "threshold": 0.8,
    "method": "Template matching",
    "imageName": "orochi_check_10.png"
  }
]
```

生成：

```python
I_OROCHI_CHECK_10 = RuleImage(roi_front=(440,40,400,100), roi_back=(440,40,400,100),
                              threshold=0.8, method="Template matching",
                              file="./tasks/Orochi/o/orochi_check_10.png")
```

- `file` 的目录 = **JSON 文件所在目录**；`imageName` 是**带扩展名的文件名**。
- 图片必须和 JSON 放在一起（或者用子目录的相对路径写进 `imageName`）。

**click**（恰好 4 个键）：

```json
[{ "itemName": "boss_detail_close", "description": "关闭首领详情",
   "roiFront": [1182, 73, 47, 43], "roiBack": [1182, 73, 47, 43] }]
```

→ `C_BOSS_DETAIL_CLOSE = RuleClick(roi_front=..., roi_back=..., name="boss_detail_close")`

**long_click**（5 个键，多 `duration`，单位秒）→ `L_xxx = RuleLongClick(..., duration=0.5, name=...)`

**swipe**（5 个键，多 `mode`，通常是 `"default"`）：

```json
[{ "itemName": "to_abyss", "description": "右侧滑到底",
   "roiFront": [1200, 400, 30, 200], "roiBack": [600, 400, 30, 200], "mode": "default" }]
```

**ocr**（7 个键）：

```json
[{ "itemName": "fire", "description": "挑战按钮",
   "roiFront": [1135, 599, 85, 49], "roiBack": [1123, 570, 106, 100],
   "mode": "Single", "method": "Default", "keyword": "挑战" }]
```

→ `O_FIRE = RuleOcr(roi=(...), area=(...), mode="Single", method="Default", keyword="挑战", name="fire")`
注意 **`roiFront → roi`、`roiBack → area`**（OCR 的形参名和图片规则不一样）。

**list**（顶层是 dict）：

```json
{
  "name": "layer_list",
  "description": "层数列表",
  "direction": "vertical",
  "type": "ocr",
  "roiBack": [126, 107, 79, 593],
  "list": [
    { "itemName": "layer_1", "roiFront": [160, 110, 60, 40] },
    { "itemName": "layer_2", "roiFront": [160, 200, 60, 40] }
  ]
}
```

生成器会用所有 `roiFront` 的**平均宽高**算 `size`，并展开出 `array=[...]`。

### 4.3 命名规则

- 变量名 = 前缀 + `itemName.upper()`（`name_transform`，`:28-40`）。
- 类名 = `<任务目录名>Assets`，例如 `tasks/Orochi/` → `class OrochiAssets`，`tasks/Component/GeneralBattle/` → `GeneralBattleAssets`。
- `RuleImage.name = Path(file).stem.upper()`，所以**图片文件名本身就是资产名**（`o_orochi.png` → `O_OROCHI` 的语义来源）。

### 4.4 重跑生成器

```powershell
cd D:\script-dev\yys\OnmyojiAutoScript-dev
.\.venv\Scripts\python.exe dev_tools\assets_extract.py
```

行为（`AllAssetsExtractor`，`dev_tools/assets_extract.py:403-421`）：

- 遍历 `tasks/*/` 的所有目录，**剔除含 `Component` 的**，再把 `tasks/Component/*/` 加进列表；
- 对每个任务目录 `rglob('*.json')`，跳过路径里含 `temp` 的文件；
- **重写该目录下的 `assets.py`**——所以一次运行会重建**所有**任务的 `assets.py`。跑之前先 `git status` 确认工作区干净，跑完 `git diff` 看有没有意外变更。
- 某个任务目录下没有任何 JSON 时，会写出 `pass` 占位并打 error 日志。

### 4.5 标注工具（annotator）

不想手写 ROI 时用它：`module/server/tool.py`（62 KB）+ `module/server/tool_router.py`，路由前缀 **`/tool/annotator`**：

- 页面：`GET /tool/annotator`；
- 会话/截图：`/annotator/api/session`、`/annotator/api/emulator/{start|stop|status|capture}`；
- 规则：`/annotator/api/rules/{schema|load|source|test|save}`、`/annotator/api/rules/image-preview`；
- 图片：`/annotator/api/images/{upload|delete-batch|clear}`、`/annotator/api/images/crop-save`。

它直接读写 `tasks/*/` 下的 JSON 和 png，**能写源码**（`rules/source/create`、`source/delete`）。配合 `module/server/app.py:36-42` 的 `CORSMiddleware(allow_origins=["*"], allow_credentials=True)`，**只在本机用，不要把端口暴露到局域网**。

## 5. 最小改动：一个按钮点不到

这是日常最高频的工作（游戏 UI 一更新就要做）：

1. **抓一张当前的截图**（annotator 的 `capture`，或从 `log/error/<时间戳>/` 里找最近一帧）。
2. **找到这个按钮对应的 JSON 条目**：
   ```powershell
   # 在整个 tasks 下搜资产名
   rg -n "boss_detail_close" tasks
   ```
   搜到的通常是 `tasks/<X>/**/click.json`。
3. **在 1280×720 的坐标系里重新框 `roiFront`**（`roiBack` 一般同步改，或整体放宽一圈）。
4. **重跑生成器**：`python dev_tools\assets_extract.py`。
5. **验证**：
   ```powershell
   & .\.venv\Scripts\python.exe -c "from tasks.Orochi.assets import OrochiAssets; print(OrochiAssets.C_BOSS_DETAIL_CLOSE.roi_front)"
   ```
   然后启动 GUI 跑这个任务，看 `log/` 里对应配置名的日志。

三个常见"改了没用"的原因：

| 现象 | 原因 |
|---|---|
| 改了 JSON 还是旧行为 | 忘了跑 `assets_extract.py` |
| 手改了 `assets.py`，下次跑生成器就没了 | `assets.py` 是生成物 |
| 模拟器上能匹配，PC 客户端不能 | 桌面模式 ROI 要多 2 px padding（`module/atom/image.py` 的 `DESKTOP_ROI_MATCH_PAD = 2`） |

## 6. 写一个新任务

以新增一个假想任务 `NewTask` 为例。**四个文件 + 两个登记点**，缺一个就会出现"任务跑不了 / 界面里看不到 / 配置不生效"。

### 6.1 目录

```
tasks/NewTask/
├── config.py        # pydantic 配置
├── script_task.py   # 入口：class ScriptTask
├── page.py          # 可选：接入图导航
├── o/               # 模板图 + 规则 JSON（通常放这里）
│   ├── new_task_button.png
│   └── image.json / click.json / ocr.json …
└── assets.py        # 生成物，先空着，跑生成器产生
```

### 6.2 `config.py`

```python
from pydantic import Field

from tasks.Component.config_base import ConfigBase, Time
from tasks.Component.config_scheduler import Scheduler


class NewTask(ConfigBase):
    scheduler: Scheduler = Field(default_factory=Scheduler)   # 必须有：enable / next_run / priority
    limit_count: int = Field(default=10, description='limit_count_help')
    limit_time: Time = Field(default=Time(minute=30), description='limit_time_help')
    enable_buff: bool = Field(default=True, description='enable_buff_help')
```

约定：

- 一律继承 `tasks/Component/config_base.py:84` 的 `ConfigBase`；
- 每个字段都带 `description='<key>_help'`，这是 GUI 里的提示文案 key（见 §7.5）；
- 加约束用 `ge= / le=`（`ConfigBase.__init__` 对越界会**回退默认值并 warning**，不会崩，`:94-112`）。

### 6.3 登记到 `ConfigModel`（必须）

`module/config/config_model.py`：

```python
# 顶部（:4-:83 那一堆 import 里挑位置）
from tasks.NewTask.config import NewTask

# 类里（跟 orochi: Orochi = ... 并列）
new_task: NewTask = Field(default_factory=NewTask)
```

字段名用**下划线小写**，`config.new_task.limit_count` 才能取到。`ConfigModel.type('new_task')` 通过 `__annotations__` 反查类名，所以类名和字段名要对应。

### 6.4 登记到 GUI 菜单（必须）

### 6.6 `script_task.py`

```python
import datetime

from module.exception import TaskEnd
from module.logger import logger
from tasks.base_task import BaseTask
from tasks.Component.GeneralBattle.general_battle import GeneralBattle
from tasks.GameUi.game_ui import GameUi
from tasks.NewTask.assets import NewTaskAssets
from tasks.NewTask.config import NewTask


class ScriptTask(GeneralBattle, GameUi, NewTaskAssets):
    def run(self):
        cfg: NewTask = self.config.new_task

        # 1) 走到目标页面（图导航）
        self.goto_page(self.pages.page_new_task)

        # 2) 主循环
        count, limit = 0, cfg.limit_count
        while count < limit:
            if not self.appear(self.I_NEW_TASK_START):
                logger.warning('未找到开始按钮，退出')
                break
            self.click(self.C_NEW_TASK_START)

            # 3) 需要打一场就用战斗组件
            if not self.run_general_battle(config=None, buff=None):
                break
            count += 1

        # 4) 写回调度器
        self.set_next_run(task='NewTask', finish=True, success=True)
        raise TaskEnd
```

要点：

- **`run()` 必须以 `raise TaskEnd` 结束**，否则调度器认为任务没跑完。
- `self.config` 是整个 `ConfigModel`，取本任务配置用 `self.config.new_task`（下划线）。
- `BaseTask` 提供 `appear / appear_then_click / ocr_appear / click / swipe / list_find / wait_until_* / ui_*`；**没有 `long_click()`**，长按请 `self.click(self.L_XXX)`（`click()` 接受 `RuleClick/RuleLongClick/RuleImage/RuleOcr`）。
- 被 `@interval_timer` 包裹的方法在 `limit` 秒内重复调用**直接返回缓存值**——"明明条件变了却没反应"先怀疑这个。
- 资产的类名来自 `assets.py` 的类定义，`class ScriptTask(..., NewTaskAssets)` 之后就能 `self.I_XXX`。

## 7. 配置系统

### 7.1 `ConfigBase` 与可用类型

`tasks/Component/config_base.py`：

| 类型 | 定义处 | GUI 控件 |
|---|---|---|
| `bool` / `int` / `float` / `str` | 原生 | 开关 / 数字框 / 输入框 |
| `Time` | `:66`，`%H:%M:%S` | 时间选择 |
| `DateTime` | `:61`，`%Y-%m-%d %H:%M:%S` | 日期时间 |
| `TimeDelta` | `:56`，`BeforeValidator(datadelta_validator)` + `format_timedelta` | 天+时分秒 |
| `MultiLine` | `:52`，`Annotated[str, WithJsonSchema({'type': 'multi_line'})]` | 多行文本 |
| `Enum(str, Enum)` | 各任务 `config.py` | 下拉框 |

**只有这些类型能被 GUI 正确渲染**：`module/server/script_router.py:124` 收到 `types` 参数后按 `integer / number / boolean / string / date_time / time_delta / time` 逐个强转，不认识的一律原样透传（`case _: pass`），非法值抛 `HTTPException(400, 'Argument type error: ...')`。

### 7.2 配置怎么变成 GUI 控件（链路）

```
GET /script/{name}/{task}/args
  → MainManager.config_cache(name).model.script_task(task)      # script_router.py:120
  → ConfigModel.gui_args(task)  → json.dumps(task_gui.schema())  # config_model.py:202-224
  → 前端按 JSON Schema 逐字段渲染
PUT /script/{name}/{task}/{group}/{argument}/value?types=...
  → 类型强转 → ConfigModel.script_set_arg(...)                   # script_router.py:124-155
```

所以**在 `tasks/<X>/config.py` 里加一个字段，GUI 会自己长出一个控件**，不用改前端、不用改 `args.json`。
唯一的特例处理：`Scheduler.success_interval / failure_interval` 的 schema `type` 被强行改成 `'string'`（`config_model.py:214-224`）。

### 7.3 保存语义（重要）

`ConfigModel.__setattr__`（`config_model.py:170-179`）：**每给配置字段赋一次值，就立刻 `logger.info('auto save config')` + `save()` 落盘**。

后果：

- 不要在循环里写 `self.config.new_task.limit_count = i`——那是 N 次磁盘写入；
- 想临时改值，用局部变量；
- `save()` 走 `write_json(self.config_name, self.model_dump())`，所以 JSON 里是**全量**的当前模型。

### 7.4 `Scheduler`（每个任务都有）

`tasks/Component/config_scheduler.py`：

```python
enable: bool = False
next_run: DateTime = DateTime.fromisoformat("2023-01-01 00:00:00")
priority: int = 5
success_interval: TimeDelta = TimeDelta(days=1)
failure_interval: TimeDelta = TimeDelta(days=1)
server_update: Time = Time(hour=9)
delay_date: int = 1          # 1-31
float_time: Time = Time(hour=0)
```

## 8. GameUi 图导航（dev 分支的重点）

完整说明见 `tasks/GameUi/USAGE.md`。这里只给"够用"的版本。

### 8.1 概念

| 概念 | 说明 |
|---|---|
| `Page(recognizer, priority=50, cost=..., category=..., key=..., name=..., register=True)` | 一个界面 = 一个 Page |
| `recognizer` | `RuleImage` / `RuleOcr` / `any_of(...)` / `all_of(...)` / `not_(...)` / 自定义 `def check(task) -> bool` |
| `page_a.connect(page_b, action, key="a->b", cost=...)` | 有向边；`action` 可以是 `RuleClick` 或 `sequence(...)` / `conditional_action(cond, action)` |
| `priority` | 1-100，**越高越先被判定**（越界自动 clamp 并 warning）；默认 50 |
| `cost` | 走这条边的代价，默认 1；用于让导航绕开又慢又不稳的路 |
| 四阶段 hook | `on_enter_success` / `on_enter_failure` / `on_leave_success` / `on_leave_failure` |
| `NavigatorSession` | **任务级**运行态（`tasks/GameUi/session.py`），跨任务不共享 |
| `PageRegistry.load_all_pages()` | `registry.py:70` 自动 import 所有 `tasks/*/page.py` |
| `goto_page(dest)` | Dijkstra 规划；每步 2 帧确认；单条边连失 3 次触发关弹窗；超时抛 `GamePageUnknownError` |

### 8.2 真实样例（`tasks/Orochi/page.py` 全文 16 行）

```python
from tasks.GameUi.default_pages import page_exploration, page_soul_zones, page_shikigami_records
from tasks.GameUi.matcher import any_of
from tasks.GameUi.page_definition import Page
from tasks.GlobalGame.assets import GlobalGameAssets
from tasks.Orochi.assets import OrochiAssets

page_orochi = Page(any_of(OrochiAssets.I_OROCHI_CHECK_10, OrochiAssets.I_OROCHI_CHECK_11,
                          OrochiAssets.I_OROCHI_CHECK_12, OrochiAssets.I_OROCHI_CHECK_13))
page_orochi.connect(page_exploration, GlobalGameAssets.I_UI_BACK_YELLOW, key="page_orochi->page_exploration")
page_soul_zones.connect(page_orochi, OrochiAssets.I_OROCHI, key="page_soul_zones->page_orochi")
page_orochi.connect(page_shikigami_records, OrochiAssets.I_SHI_RECORDS,
                    key="page_orochi->page_shikigami_records", cost=2)
page_shikigami_records.connect(page_orochi, GlobalGameAssets.I_UI_BACK_YELLOW,
                               key="page_shikigami_records->page_orochi", cost=2)
```

### 8.3 category 与构图范围

- 不传 `category` 时按**文件路径**推断；`tasks/GameUi/` 下的页面默认 `global`。
- 运行时构图用"**当前页分类 + 目标分类 + `global`**"；当前页未知时退化为"目标分类 + `global`"。
- 识别用"**本任务分类 + 目标分类 + `global`**"。
- 所以：跨任务的公共界面（主界面、探索、商店…）全部登记在 `tasks/GameUi/default_pages.py`，任务私有页面留在自己目录。

### 8.4 迁移现状（写新代码时的判断依据）

- 全仓 **只有 6 个 `page.py`**：`tasks/GameUi/page.py`(2878 B)、`tasks/ActivityShikigami/page.py`(4017)、`tasks/Exploration/page.py`(2460)、`tasks/Orochi/page.py`(1028)、`tasks/OtherWorldTwilight/page.py`(631)、`tasks/DailyTrifles/page.py`(471)。
- `Page(` 出现 110 处，`Transition(` 只有 2 处 → 新的 `connect()` API 是主流，旧 `page_x.link(...)` 在部分 `page.py` 里已被整段注释。
- **结论**：新任务建议用 `Page + connect`；改造老任务时别一次性全搬，先在 `goto_page` 里替换掉一段硬编码流程。

已废弃（见到就换）：`ui_goto` / `ui_goto_page` / `ui_get_current_page` / `try_close_unknown_page` / `run_additional`，旧字段 `ui_current` / `ui_close` / `links`。

### 10.3 分辨率硬约束

全流程固定 **1280×720**：

- `screenshot.py:241` `logger.critical('Please set emulator resolution to 1280x720')`；
- `screenshot.py:245` `return self.image.shape == (720, 1280, 3)`；
- 桌面模式 `desktop_impl.py:1007 desktop_window_set_size(width=1280, height=720)`，失败时提示"请以管理员身份运行 OAS，或手动把游戏窗口设为 1280x720"。

### 10.4 多开（一个配置一个实例）

## 13. 调度 / 多开 / 风控

### 13.1 三种排队规则（`module/config/scheduler.py`，96 行）

| 规则 | 行为 |
|---|---|
| `ScheduleRule.FILTER` | 用 `Filter(regex=r"(.*)", attr=["command"])` 按 `ConfigManual.SCHEDULER_PRIORITY` 的字符串过滤/排序 |
| `ScheduleRule.FIFO` | 按 `next_run` 升序；**`Restart` 永远被插到最前**（remove + insert(0)） |
| `ScheduleRule.PRIORITY` | 按 `priority` 分组，组内 FIFO，再按组名排序合并 |

`SCHEDULER_PRIORITY` 在 `module/config/config_manual.py`，形如
`Restart > SoulsTidy > KekkaiUtilize > ... > TrueOrochi > RichMan > MetaDemon > ...`。
想调整任务顺序就改这个字符串（用 `>` 分隔），不用改调度器代码。

已知无害瑕疵：`priority()` 第 75 行的 `sorted(...)` 结果被丢弃。

### 13.2 让任务"下一次什么时候跑"

- 任务内：`self.set_next_run(task='Xxx', finish=True, success=True, server=..., target=...)`；
- 外部触发：`PUT /script/{name}/{task}/sync_next_run?target_dt=...`（内部 `config.task_delay` + `config.get_next()` + `broadcast_state`）；
- 间隔由 `scheduler.success_interval` / `failure_interval`（`TimeDelta`）决定，失败时用 `failure_interval`。

### 13.3 风控与排队

- `module/config/anti_ban.py:6 class AntiBanGuard`：休息窗口（`anti_ban_guard`，`script.py` 里在 `loop()` 中被检查）；
- `module/config/instance_guard.py`：多开 token 排队，见 §10.4。
